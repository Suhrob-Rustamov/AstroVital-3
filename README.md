# AstroVital

Backend: **Python 3.9+, FastAPI + uvicorn**, база SQLite. Frontend — статические `index.html` / `admin.html` (дизайн без изменений).

## Структура проекта
```
astrovital/
├── main.py                  # точка входа: python3 main.py | uvicorn main:app
├── requirements.txt
├── app/
│   ├── main.py              # create_app(): сборка FastAPI, роутеров, статики
│   ├── config.py            # настройки и константы (БД, куки, должности, 7 дней)
│   ├── database.py          # схема SQLite и db()
│   ├── bootstrap.py         # первый запуск: схема + администратор
│   ├── errors.py            # HttpError, заголовки безопасности, JSON-only POST
│   ├── security.py          # scrypt-пароли, троттлинг входа, сессии, cookie, need_user/need_admin
│   ├── utils.py             # время, расчёт возраста
│   ├── questionnaire.py     # поля анкеты, пороги, evaluate()
│   ├── services/
│   │   ├── auth.py          # user_out, вход/выход, смена пароля
│   │   └── health.py        # анкеты, графики, недельные отчёты, 24-часовое окно
│   └── routers/
│       ├── pages.py         # / и /admin
│       ├── auth.py          # регистрация, вход, профиль, пароль
│       ├── health.py        # анкета, история, графики
│       ├── sos.py           # SOS астронавта
│       └── admin.py         # /admin/api/*
└── frontend/
    ├── index.html, admin.html
    └── static/{css,js}/     # стили и скрипты (index.*, admin.*), отдаются по /static
```
Правило слоёв: routers → services → database/config. Роутеры только принимают запрос и отдают ответ, логика живёт в services.

## Запуск
```
pip install -r requirements.txt
python3 main.py              # или: uvicorn main:app --host 127.0.0.1 --port 8000
```
Схема БД изменилась (дата рождения вместо возраста, таблица `weekly_reports`): старый `astrovital.db` нужно удалить.
- Приложение астронавта: http://127.0.0.1:8000
- Админ-панель: http://127.0.0.1:8000/admin

При первом запуске создаётся база `astrovital.db` и администратор.
Учётные данные по умолчанию: логин `admin`, пароль `AstroVitalAdmin2026!`.
Измените пароль в админ-панели перед использованием вне локальной разработки. Для переопределения при первом запуске
новой базы задайте переменные окружения `ADMIN_USERNAME` / `ADMIN_PASSWORD`.

Переменные окружения: `HOST`, `PORT`, `ASTROVITAL_DB`, `SECURE_COOKIES=1` (включать за HTTPS).

## Безопасность
- Пароли: scrypt + индивидуальная соль; исходный пароль нигде не хранится и не отдаётся (в т. ч. админу).
  Админ может только сбросить пароль: выдаётся временный, при входе астронавт обязан его сменить.
- Сессии: случайный токен в HttpOnly SameSite=Strict cookie, в БД хранится только его хеш. Cookie админа и астронавта раздельные.
- Админ-API недоступны без сессии админа; астронавт видит только свои данные.
- Ограничение 24 ч проверяется на сервере (серверное время UTC, транзакция BEGIN IMMEDIATE — гонка двух запросов невозможна).
- Ограничение попыток входа (5 за 5 минут), CSP и защитные заголовки, JSON-only POST.
- Пароль администратора по умолчанию опубликован в этом README и предназначен только для локальной разработки.
- Для продакшена: задайте собственный `ADMIN_USERNAME` / `ADMIN_PASSWORD`, включите HTTPS (reverse proxy) и резервное копирование `astrovital.db`.

## Регистрация
Имя и фамилия 3–16 символов, должность — из списка, пароль 3–8 символов, дата рождения (возраст 18–90 считается автоматически и нигде не хранится).
Проверка на клиенте и на сервере.

## Графики
- Ежедневный график: день N = N-я фактически отправленная анкета текущего семидневного периода (оси «День 1…7»). Пропущенный день не создаёт точки.
- До первой анкеты показываются демонстрационные стабильные значения (пунктир, пометка «демо»).
- После 7-й анкеты неделя сохраняется в `weekly_reports` и показывается под основным графиком; начинается новый период.
- На Overview, пока в новом периоде нет анкет, показывается график последней завершённой недели. После отправки следующей анкеты график переключается на новый период и обновляется вместе с данными анкеты.
- API: `GET /api/health/charts` → `{cycle, weeks}`.

## Тестовые пользователи
Демо-профили и их синтетические анкеты можно загрузить отдельно от обычного запуска приложения:
```
python demo_users.py seed
```
Создаются профили со стабильными, требующими наблюдения и критическими показателями; у каждого — 14 ежедневных анкет.
Пароль всех профилей: `demo1234`. Для удаления профилей и связанных с ними анкет, графиков, SOS-запросов и сессий:
```
python demo_users.py remove
```
Скрипт работает с базой из `ASTROVITAL_DB` или с `astrovital.db` по умолчанию. Данные исключительно тестовые,
не являются медицинской рекомендацией; для повторной загрузки сначала удалите демо-профили.

## Таблицы
users, admins, sessions, health_records (одна анкета), health_metrics (каждый показатель анкеты),
weekly_reports (сохранённые недельные графики), sos_requests. История хранится без ограничений.

## Пороговые значения
Заданы в `app/questionnaire.py` (список `FIELDS`, поле `bands`) на основе общих клинических ориентиров и практики
космической медицины (в т.ч. лимиты NASA по радиации). Это прототипные значения: перед реальным применением
их должен утвердить врач/полётный хирург. Оценка предварительная, не диагноз.
